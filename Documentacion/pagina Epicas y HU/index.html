UNA BASE COMPARTIDA

El alcance, sin sorpresas.

Solicitante, agente, supervisor y administrador. Cada usuario tiene un único rol vigente; solicitante ve solo sus tickets y agente, supervisor y administrador consultan todos.

  • Registro de nuevas solicitudes desde el portal.
  • Contacto y avisos Telegram en memoria; sin integración con tickets reales.
  • Asignación, transiciones y actividad implementadas; notas y conversación pendientes.
  • Seis estados; altas en Creado y sin agente. Cambios manuales mediante nueve transiciones autorizadas.

Código presente ≠ entrega validada.

Hay bases técnicas implementadas. El recorrido operativo del ticket está implementado; la entrega en Telegram real requiere cuentas y configuración externas.

ESCENARIO DE PLANIFICACIÓN · FECHAS POR CONFIRMAR

Un plan para construir.

Este escenario alternativo conserva un Sprint 0 y seis sprints estimados de desarrollo/cierre. La numeración y alcance de referencia están en Planificacion/SprintBacklog.md; no representa ejecución confirmada.

Cómo leer los tiempos: las horas de una tarea o HU son horas-persona acumuladas entre A, B y C, no su duración en el calendario. Incluyen desarrollo, integración y pruebas específicas. La reserva cubre revisiones, coordinación e imprevistos. Los fines de semana del calendario no implican disponibilidad diaria confirmada.

Acuerdos de trabajo y cierre

Reunión diaria de 10 minutos, revisión entre compañeros y demostración al terminar cada sprint. Cada tarea tiene una persona responsable y revisión de otra.

  • Historia terminada: criterios revisados, permisos comprobados, interfaz integrada y pruebas del flujo aprobadas.
  • Reservar 8 horas del equipo en cada sprint de desarrollo (48 h en S01–S06); el Sprint 0 contempla otras 8 h sujetas a disponibilidad para coordinación, revisión y bloqueos; no iniciar nuevas funciones durante S06.
  • Si una dependencia no se resuelve o la carga excede la capacidad, registrar el riesgo y acordar la decisión con el equipo; no reducir el alcance de forma silenciosa.
  • Fecha de entrega por confirmar: demostrar el recorrido implementado y entregar código, manual y evidencia; el calendario estimado no acredita una entrega completa.

Fuera del MVP: las 78 historias originales restantes. HU-02-09 y HU-04-04 siguen sin sprint; revisar la cobertura del historial antes de planificarlas. SLA es trabajo futuro: aún no hay cálculo ni ejemplos operativos.

Ver tecnologías y función de cada una

Versiones declaradas en el proyecto y verificadas con los chequeos locales del 6-nov-2026. La ejecución remota de CI se revisa por separado.

Interfaz y navegación
Angular 22.2 · TypeScript 6 · RxJS 7.8. Componentes, rutas, formularios y comunicación con la API.
Diseño de la aplicación
Tailwind CSS 4.1 · PostCSS. Estilos y utilidades visuales del frontend Angular.
Servidor
Node.js ≥22.23.1 · Express 5 · TypeScript 6. API HTTP, lógica del servidor y gestión de sesiones.
Persistencia
PostgreSQL 17 · pg · SQL. Conexión, transacciones, migraciones y datos de desarrollo; sin ORM.
Entorno local
Podman Compose · dotenv · npm. Contenedor de PostgreSQL, variables de entorno y scripts de trabajo. Gestor declarado: npm 10.9.8.
Comunicación
Telegram Bot API · fetch. Avisos generales después del commit, sin lectura de mensajes. Contacto personal independiente mediante enlace público.
Protección y validación
Argon2 · Zod · Helmet · CORS · express-rate-limit. Dependencias para contraseñas, entradas, cabeceras, orígenes y límites de peticiones. Controles cubiertos por pruebas unitarias y de integración locales.
Pruebas
Vitest · Supertest · jsdom. Pruebas unitarias, comprobaciones HTTP y entorno de pruebas del frontend.
Calidad y colaboración
ESLint · Prettier · Git · GitHub Actions. Revisión estática, formato y flujo de cambios. El archivo ci.yml configura comprobaciones del frontend y backend, con PostgreSQL para el backend; no se comprobaron resultados de ejecuciones.
